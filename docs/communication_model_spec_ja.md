## 1. 本書の目的

本書は、大阪湾の実測AISデータから得た通信性能を、時間軸上のAIS通信として再現するための通信モデルを定義する。

通信モデルの最終目的は、単に実測グラフを再描画することではない。距離、船舶Class、船体長、将来取得するアンテナ高などの条件を変えたときに、AIS位置情報の受信、推定欠落、情報鮮度がどのように変化するかを評価できるようにする。

さらに、過去ログから得た大阪湾の交通を基準シナリオとして再現し、船舶数・送信負荷を段階的に増やしたときのスロット競合、欠落率、情報鮮度違反率の変化を求める。これにより、研究室受信局から概ね30km以内を主な評価範囲として、現在のAIS通信が十分に機能しなくなる交通負荷の限界点を定量的に検討する。

## 2. 研究上の位置付け

研究全体を次の3段階に分ける。

1. 第1段階: 実測AISログから、距離・Class・時間帯・船体長別の推定欠落率と情報鮮度違反率を求める。
2. 第2段階: 第1段階の結果から通信モデルを作り、AIS送信と受信を時間軸上で再現し、実測値との一致を検証する。
3. 第3段階: 過去ログから得た大阪湾の基準交通を増減させ、AISのアクセス方式、スロット利用、競合を再現し、交通負荷に対する通信性能の限界点を評価する。

第1段階で求めた欠落は、送信側ログと照合した真のパケット損失ではなく、AIS規格上の期待送信間隔と実受信間隔から推定した値である。したがって、第1版の通信モデルは、原因を個別に説明する物理モデルではなく、研究室受信地点で観測された結果を再現する経験的モデルとして扱う。

現在の学習データは研究室にある2台のAIS受信機のファイルを統合したデータであるため、CM-E1は単一受信機または単一アンテナの性能モデルとは呼ばない。「研究室の統合AIS受信系で観測された経験的通信モデル」と位置付ける。2台の受信機、アンテナ構成、稼働期間、重複除外規則が判明するまでは、個別機器の性能差をCM-E1の説明へ含めない。

過去ログは、研究室の統合AIS受信系で受信できた船舶とメッセージの記録であり、大阪湾を航行した全船舶の完全な真値ではない。まったく受信できなかった船舶はログから復元できないため、第3段階の交通モデルは「観測ログを基準とした大阪湾交通モデル」と呼ぶ。交通量倍率と限界点の結果には、この観測範囲上の制約を明記する。

## 3. モデル化の基本原則

### 3.1 受信結果を生成し、評価指標は既存解析コアで計算する

通信モデルは、各送信予定メッセージについて「受信した／受信しなかった」を決定する。

推定欠落率と情報鮮度違反率を別々の確率として直接生成してはならない。通信モデルが生成した受信メッセージ列を既存の`AnalysisEngine`へ入力し、現在と同じ`LossEstimator`と`FreshnessEvaluator`で両指標を再計算する。

```text
船舶の航跡・状態
        ↓
規格に基づく理想送信時刻の生成
        ↓
通信モデルによる受信／非受信判定
        ↓
受信できたメッセージ列
        ↓
既存の共通入力・解析・空間集計
        ↓
推定欠落率・情報鮮度違反率・地図表示
```

この構成により、実測とシミュレーションに同じ評価方法を適用できる。

### 3.2 段階的に高度化する

| 段階 | モデル | 目的 |
| --- | --- | --- |
| CM-E1 | 距離帯×Class別の経験的受信モデル | 最小構成で送受信シミュレーションを成立させる |
| CM-E2 | 距離帯×Class×船体長別モデル | 船体長をアンテナ高の代理変数として取り込む |
| CM-E3 | 連続欠落を考慮した状態依存モデル | 情報鮮度を左右する欠落の連続性を再現する |
| CM-P1 | 送受信アンテナ高・機器特性・伝搬モデル | 物理条件を変更できるモデルへ進める |
| CM-N1 | スロット競合・混信・アクセス方式 | 船舶数増加などの通信混雑を再現する |

最初の実装対象はCM-E1とし、既存データで検証後にCM-E2、CM-E3へ進む。CM-P1は受信設備情報の取得後、CM-N1は交通モデルとAISアクセス方式の詳細設計後に実装する。

### 3.3 最終構想における処理の流れ

最終構想では、現在の実測解析・CM-E1を捨てず、交通モデルとネットワーク混雑モデルを後段へ追加する。

```text
過去AISログ
    ↓
観測された実航跡・船種・Class・時刻分布の抽出
    ↓
基準交通シナリオ（交通量1.0倍）
    ↓
交通量増加シナリオ（1.25倍、1.5倍、2.0倍等）
    ↓
全船舶の理想AIS送信予定
    ↓
CM-N1によるスロット割当・競合・通信混雑
    ↓
CM-E1／CM-E2／CM-P1による距離・Class・物理条件の受信判定
    ↓
受信成功したメッセージ列
    ↓
既存AnalysisEngine
    ↓
欠落率・情報鮮度違反率・位置把握遅延・地域別分布
    ↓
交通負荷に対するAIS通信限界の評価
```

CM-E1は各送信を独立判定するため、CM-E1だけで船舶数を増やしても、欠落件数は増えるが欠落率が交通量に応じて悪化するとは限らない。船舶数増加の影響を研究するには、交通モデルとCM-N1が必須である。

### 3.4 基準交通と通信混雑の二重計上防止

CM-E1は実測結果から作る経験的モデルであり、学習期間に存在した通信混雑、干渉、受信設備の状態等の影響を完全には分離できない。したがって、CM-N1の競合損失をCM-E1へ無条件に掛け合わせてはならない。

交通量1.0倍のシナリオでは、CM-N1を含む全体結果が基準期間の実測またはCM-E1の受信傾向を再現するよう校正する。交通量増加時は、1.0倍からの追加的な混雑悪化を評価する。CM-N1詳細設計時に、次のいずれを採用したかをモデル版へ記録する。

1. CM-E1を基準状態とし、CM-N1は1.0倍からの相対的な悪化分だけを加える。
2. 伝搬・受信要因をCM-P1等へ分離し、CM-N1と独立に再校正する。

同じ欠落要因をCM-E1とCM-N1で二重に数えていないことを、1.0倍シナリオの再現性確認によって検証する。

## 4. CM-E1の仕様

### 4.1 入力

1件の理想送信予定に対し、少なくとも次の情報を入力する。

| 入力 | 必須 | 用途 |
| --- | --- | --- |
| 送信予定日時 | 必須 | 時系列処理と再現性 |
| MMSI | 必須 | 船舶状態と乱数系列の識別 |
| メッセージ種別 | 必須 | Type 1/2/3/18の送信周期決定 |
| Class A/B | 必須 | パラメータ表の選択 |
| 緯度・経度 | 必須 | 受信局距離の計算 |
| SOG、航行状態、変針状態 | 必須 | 規格上の理想送信時刻の生成 |
| COGまたは真船首方位 | 表示時に必要 | 船舶記号と航跡の生成 |
| 受信局プロファイル | 必須 | 受信局位置と適用期間の特定 |
| 船体長 | CM-E1では任意 | CM-E2で使用 |
| 送信アンテナ高 | 将来 | CM-P1で使用 |

### 4.2 距離帯

- 受信局アンテナ位置から船舶位置までの距離を求める。
- 0～70kmを5km幅の距離帯へ分類する。
- 30kmは確率が切り替わる境界ではなく、考察用の基準線とする。
- 70km以上は第1版のモデル適用範囲外として記録する。

### 4.3 パラメータの作成

学習期間の実測集計から、距離帯`d`、Class`c`ごとに次を求める。

```text
expected(d,c) = observedCount(d,c) + missingCount(d,c)
estimatedLossRate(d,c) = missingCount(d,c) / expected(d,c)
receptionProbability(d,c) = 1 - estimatedLossRate(d,c)
simulationReceptionProbability(d,c)
    = (observedCount(d,c) + 0.5) / (expected(d,c) + 1)
```

率の単純平均は使用せず、対象期間内の分子と分母を合算してから確率を求める。

実測結果として表示・出力する率は補正前の値を使用する。受信判定には、0%または100%を絶対的な確率として固定しないため、Jeffreys補正を適用した`simulationReceptionProbability`を使用する。パラメータセットには補正前の率と補正後の確率を両方保存する。

十分なデータがある距離帯の確率は、距離とともに必ず悪化するような単調化や平滑化を行わず、実測集計値を保持する。局所的な増減は誤差として自動修正せず、信頼区間と標本情報を併記して評価する。単調化モデルが必要になった場合は、CM-E1を置き換えず比較用の別モデルとして追加する。

画面表示の最低基準は、既存設計と同じ次の条件とする。

- `expectedCount < 30`
- 異なるMMSIが3隻未満

通信モデルのパラメータとして採用するには、上記に加えて次の条件をすべて満たさなければならない。

- 観測日数が5日以上
- 日単位で再標本化して求めた95%信頼区間の幅が20 percentage point以内

モデル採用可否、95%信頼区間の下限・上限、期待送信数、MMSI数、観測日数をパラメータセットへ保存する。モデル用基準を満たさないセルは、画面に通常表示できる場合でも、通信モデルではデータ不足として補間または`OUT_OF_MODEL`の対象にする。

### 4.4 受信判定

送信予定ごとに、固定シードから生成した一様乱数`u`を用いる。

```text
received = u < simulationReceptionProbability(distanceBand, vesselClass)
```

- `received = true`の場合、送信予定を受信イベントとして共通入力境界へ渡す。
- `received = false`の場合、受信イベントは生成せず、シミュレーター内部の判定履歴だけに残す。
- 同じ入力、モデル版、パラメータ、乱数シードでは同じ結果を再現できなければならない。

### 4.5 データ不足時の扱い

CM-E1のフォールバック順序を次とする。

1. 同じ距離帯・同じClassの十分なパラメータ
2. 対象距離帯の近距離側と遠距離側の両方に、同じClassの十分なパラメータがある場合に限り、距離帯中心間の線形補間
3. 両側の十分なパラメータがそろわず補間できない場合は、`OUT_OF_MODEL`として受信判定を行わない

Class AとClass Bを混合した確率へのフォールバックは行わない。片側の値だけを用いた最近傍補完や、観測範囲外への外挿も行わない。70km以上は初回モデルの適用範囲外とし、受信不能と同一視しない。

`OUT_OF_MODEL`は受信失敗を意味しない。該当する送信予定は、推定欠落率・情報鮮度違反率の分子と分母へ含めず、適用外件数・時間・船舶数を診断情報として保存する。

船舶が`OUT_OF_MODEL`へ入った時点で解析区間を閉じる。モデル適用範囲へ戻ったときは、範囲外になる前の最終受信との間を欠落または鮮度違反として計算しない。戻った後の最初の受信成功を新しい解析区間の始点とする。

## 5. CM-E2の仕様

CM-E2では、距離帯`d`、Class`c`、船体長区分`l`ごとに受信確率を求める。

```text
receptionProbability(d,c,l)
    = observedCount(d,c,l)
      / (observedCount(d,c,l) + missingCount(d,c,l))
```

船体長区分は既存解析と同じ次の区分を使用する。

- 50m未満
- 50～99m
- 100～149m
- 150～199m
- 200～249m
- 250m以上
- 不明・範囲外

十分なデータがないセル、または船体長不明の船舶は、同じ距離帯・ClassのCM-E1パラメータへフォールバックする。

船体長はアンテナ高そのものではない。CM-E2の結果には船種、航路、運航範囲などの交絡が含まれるため、船体長による物理的因果を直接表すモデルとは呼ばない。

## 6. CM-E3の仕様方針

独立した受信判定だけでは、同じ平均欠落率を再現しても、連続欠落の長さが実測と異なり、情報鮮度違反率を再現できない可能性がある。

そのためCM-E3では、直前の送信予定が受信されたか否かを状態として持つ2状態モデルを候補とする。

```text
P(loss at t | received at t-1)
P(loss at t | lost at t-1)
```

実測受信間隔から挿入した推定欠落列を用いて遷移確率を学習する。データ不足の場合はCM-E1またはCM-E2の独立確率へフォールバックする。

CM-E3の採用可否は、CM-E1で推定欠落率は再現できるが情報鮮度違反率を再現できないことを確認した後に決定する。

## 7. 理想送信時刻の生成

- 現在の`SpecificationReportRatePolicy`を共通利用する。
- Type 1/2/3/18を対象とする。
- 連続する2件の有効な実受信位置を始点`t0`、終点`t1`とする。
- `t0`の船速、航行状態、Class BのCS/SO、変針状態から期待送信間隔を決定する。
- 現在の欠落推定と同じ規則で、`t0`と`t1`の間に本来送信されたと推定する時刻を挿入する。
- 挿入時刻の位置は、実測点間をUTM 53N上で直線補間する。
- 挿入した送信予定の船速、航行状態、変針状態は`t0`の値を引き継ぎ、`t1`で`t1`の状態へ更新する。
- 30分以上の実測航跡断絶は補間せず、別シミュレーション区間として扱う。
- 前後位置の距離差が30kmを超える区間は航跡再構成に使用しない。
- 無効位置を含む区間は航跡再構成に使用しない。

実測ログから再構成した送信列は、欠落中の真の航跡・操船状態ではなく、現在の欠落推定と同じ仮定に基づく推定送信列であることを結果へ明記する。

## 8. 出力

通信モデルは、各送信予定について内部的に次を出力する。

| 出力 | 内容 |
| --- | --- |
| 判定 | `RECEIVED`、`LOST`、`OUT_OF_MODEL` |
| 適用モデル版 | CM-E1、CM-E2等 |
| 適用パラメータキー | 距離帯、Class、船体長帯等 |
| 適用受信確率 | 0～1 |
| 乱数シード・系列識別 | 再現性確保用 |
| フォールバック有無 | パラメータ不足の確認用 |

研究結果としての推定欠落率、情報鮮度違反率、2km格子・距離帯別集計は、受信できたイベントを既存解析コアへ入力して生成する。

## 9. パラメータセットの管理

正式な通信モデルとパラメータセットはSQLiteへ保存する。CSVは人による確認、研究資料への添付、他環境との共有に使用する。CSVだけを正式なモデル保存先とはしない。

保存済みモデルは上書きしない。学習条件または計算方法を変更した場合は、新しいモデルIDと版を発行する。シミュレーション結果には、必ず使用したモデルIDと版を記録する。

通信モデルのパラメータセットには、少なくとも次を保存する。

- モデルIDとモデル版
- 作成日時
- 学習期間
- 除外日と除外理由
- 受信局プロファイルID
- 解析条件ID
- 対象メッセージ種別
- 距離帯定義
- 船体長区分定義
- セルごとのobserved、missing、expected、MMSI数、観測日数
- 受信確率
- データ不足判定
- 元データまたは解析runを識別する情報

確率だけを保存せず、根拠となる分子・分母を必ず保存する。距離帯×Class別の全パラメータとモデルメタデータはCSVへ出力できなければならない。

保存構造の候補は次のとおりとする。

| 保存単位 | 内容 |
| --- | --- |
| `communication_model` | モデルID、版、モデル種別、学習期間、受信局、解析条件、作成日時、説明 |
| `communication_model_excluded_date` | モデルID、除外日、除外理由 |
| `communication_model_parameter` | モデルID、距離帯、Class、分子・分母、標本情報、生の率、補正確率、信頼区間、採用可否 |
| `simulation_run` | 使用モデルID、入力期間、乱数シード、開始・終了状態、実行条件 |

## 10. 学習と検証

同じ期間をパラメータ作成と妥当性確認の両方に使用しない。

CM-E1の初回学習・検証期間は次のとおりとする。

| 用途 | 期間 |
| --- | --- |
| 学習 | 2025-11-01～2025-11-30。ただし2025-11-03、2025-11-04を除外 |
| 検証 | 2025-12-01～2025-12-31。正式結果では除外日なし |

2025-11-03、2025-11-04は大量の重複が確認されたため、学習対象から除外する。2025年12月は全31日で解析5分枠が288枠あり、入力・復号診断も安定しているため、正式な検証結果では除外日を設けない。12月20日は位置利用不可件数、12月26日は重複件数が同月内で相対的に多いため、この2日を除いた感度確認も実施する。ただし、感度確認用の除外結果を、理由なく正式結果へ置き換えない。

### 10.1 比較項目

- 距離帯×Class別の推定欠落率
- 距離帯×Class別の情報鮮度違反率
- 船体長×距離帯×Class別の両指標
- 25～35kmの移行帯の形状
- 連続欠落長の分布
- データ不足セルと適用外件数

### 10.2 評価値と妥当性判定

- 実測値とシミュレーション値の差（percentage point）
- 距離帯ごとの絶対誤差
- 期待送信数で重み付けした平均絶対誤差
- Class A/B別の誤差
- 情報鮮度違反率の誤差

CM-E1の妥当性は、単一の固定誤差だけではなく、次の3点で判断する。

1. 距離を入力せずClass A/B別の全体受信確率だけを使用する基準モデルを作り、検証期間に対する重み付き平均絶対誤差をCM-E1と比較する。CM-E1の誤差が基準モデルより小さいことを、距離をモデルへ含める有効性の条件とする。
2. 日別変動または信頼区間を用い、シミュレーション値が実測データの自然な変動範囲と整合するか確認する。
3. 距離増加に伴う性能悪化、25～35kmの移行帯、Class A/B差が再現されるか確認する。

推定欠落率を再現できても情報鮮度違反率を再現できない場合は、CM-E1全体を失敗とは判定しない。独立受信確率では連続欠落を表現できないことを示す結果として扱い、CM-E3の必要性を判断する。

### 10.3 反復実行

確率モデルの偶然性を確認するため、初回検証は固定した30個の乱数シードで30回実行する。各指標について平均、中央値、最小、最大、95%相当の変動範囲を出力する。30回の結果で平均値や変動範囲が安定しない場合だけ100回へ増やす。

GUIで1回の航跡再生を行う場合は、利用者が単一の乱数シードを指定できるようにする。研究用の集計結果では30回の結果を使用し、特定の乱数シードだけを選んで結論を出さない。

## 11. ソフトウェア構成方針

既存GUIや解析コアへ通信判定を直接埋め込まない。候補となる責務は次のとおりとする。

| 構成要素 | 責務 |
| --- | --- |
| `IdealTransmissionGenerator` | 航跡とAIS状態から理想送信予定を生成 |
| `CommunicationModel` | 送信予定の受信／非受信を判定する境界 |
| `EmpiricalReceptionModel` | CM-E1、CM-E2の確率判定 |
| `StatefulReceptionModel` | CM-E3の状態依存判定 |
| `CommunicationParameterSet` | 学習条件とセル別パラメータを保持 |
| `SimulatedMessageSource` | 受信できたイベントを`MessageSource`相当の境界へ供給 |
| `SimulationRun` | 入力条件、モデル版、シード、実行状態を保持 |
| `SimulationValidationService` | 実測集計とシミュレーション集計を比較 |

パッケージ候補は`ais.simulation.traffic`、`ais.simulation.communication`、`ais.simulation.validation`とする。

### 11.1 通信モデル作成画面

集計画面へ「通信モデル」タブを追加し、次の手順でモデルを作成する。

1. モデル種別、学習期間、除外日、受信局、解析条件を指定する。
2. 「パラメータを試算」で、距離帯×Class別の分子・分母、生の率、補正確率、信頼区間、標本情報、採用可否を表示する。
3. 内容を確認した利用者が「モデルとして保存」を実行したときだけ、モデルIDと版を発行してSQLiteへ保存する。
4. 保存済みモデルは編集・上書きせず、条件を変更する場合は新しいモデルを作成する。
5. 全パラメータをCSVへ出力できるようにする。

モデル作成画面を表示しただけで自動的にモデルを保存してはならない。データ不足、除外日、対象期間の未解析日がある場合は、正式保存前に警告する。

### 11.2 妥当性確認画面

妥当性確認画面では、検証期間の実測、CM-E1の30回平均、30回の95%相当変動範囲、距離を使用しない基準モデルを同じ距離帯グラフへ表示する。推定欠落率と情報鮮度違反率を切り替え、Class A/Bは色とマーカー形状を分け、30km境界を細い破線で示す。

比較表には、距離帯、Class、実測値、シミュレーション平均・変動範囲、実測との差、実測信頼区間、基準モデルとの差、期待送信数、MMSI数、観測日数、`一致・要確認・適用外`判定を表示する。

全体要約には次を表示する。

- CM-E1の重み付き平均絶対誤差
- 基準モデルの重み付き平均絶対誤差
- 基準モデルからの改善率
- 実測変動範囲に入った距離帯数
- 25～35kmの移行傾向の再現状況
- Class A/B差の再現状況
- 欠落率と情報鮮度違反率それぞれの再現状況

画面と同じ内容をCSVとPNGへ出力し、モデルID・版、学習期間、検証期間、除外日、反復回数、乱数シードを記載する。

### 11.3 シミュレーション地図表示

シミュレーション再生では、次の2種類の位置を区別する。

- シミュレーション上の真位置: 過去ログ間を補間して再構成した現在位置
- 受信表示位置: 通信モデルで最後に受信成功したAIS位置

受信表示位置は現在と同じ通常の船舶記号で描画し、正常・注意・鮮度違反を塗り色で示す。シミュレーション上の真位置は灰色の細い輪郭記号で描画し、両位置が離れた場合は薄い破線で接続する。真位置はチェックボックスで表示・非表示を切り替えられ、研究・検証用の初期状態では表示する。

「真位置」はGPS等で別途取得した真値ではなく、過去ログ間を補間したシミュレーション上の位置であることを画面と出力へ明記する。

船舶選択情報には、最後に受信してからの経過時間、両位置の距離差、現在の受信確率、直前判定、適用モデル、距離帯を表示する。

## 12. 受入条件

### 12.1 CM-E1初回実装

- 過去ログの実航跡から理想送信予定を生成できる。
- CM-E1のパラメータを学習期間のSQLite集計から生成できる。
- 距離帯とClassに応じて受信／非受信を判定できる。
- 同じ乱数シードで同じ結果を再現できる。
- 受信イベントを既存解析コアへ入力できる。
- 実測とシミュレーションの欠落率・鮮度違反率を同じグラフまたは表で比較できる。
- 学習期間と検証期間が結果に明記される。
- データ不足、フォールバック、適用範囲外の件数を確認できる。
- CM-E1で情報鮮度を再現できない場合、その差を隠さずCM-E3の必要性として報告できる。

### 12.2 最終構想の受入条件

- 過去ログから日、時間帯、航路、Class、船体長等を保持した基準交通シナリオを作成できる。
- 基準交通に対し、指定した交通量倍率で仮想船舶または航海を追加できる。
- 追加船舶が陸上を航行する、非現実的に重なる、元航跡の時間関係を壊す等の異常を診断できる。
- 各シナリオについて、全船舶の理想送信予定とスロット負荷を生成できる。
- CM-N1によりスロット競合と交通混雑に起因する受信失敗を計算できる。
- 交通量1.0倍で実測傾向を再現し、CM-E1等との二重計上がないことを説明できる。
- 交通量倍率ごとに、30km以内の欠落率、情報鮮度違反率、位置把握遅延、Class別・地域別結果を比較できる。
- 同じモデル版、交通シナリオ、seedでは同じ結果を再現できる。
- 限界点の判定基準、入力条件、適用範囲、観測ログ由来の制約を結果へ明記できる。
- 交通量倍率に対する性能曲線と、限界点候補を表・CSV・PNGへ出力できる。

## 15. 実装順序

### 15.1 初期通信モデルと妥当性確認

1. S1「モデル作成基盤」: schema version 4、CM-E1試算、パラメータ確認、明示保存、版管理を実装する。
2. S2「理想送信と通信判定」: 実航跡からの理想送信列、決定論的乱数、CM-E1、距離なし基準モデル、受信イベント変換を実装する。
3. S3「シミュレーション地図再生」: シミュレーションモード、真位置overlay、受信位置、再生操作、船舶詳細を実装する。
4. S4「妥当性確認」: schema version 5、固定seed 30回、実測比較、CSV・PNG、進捗・中止を実装する。
5. S5「複数月評価」: 任意期間、月単位交差検証、複数月モデル、時期・設備期間別の安定性を評価する。

### 15.2 交通量増加とAIS限界点評価

6. S6「大阪湾交通モデル・仮想船舶生成」: 観測ログを航跡ライブラリとして整理し、基準交通と交通量倍率別シナリオを生成する。交通量1.0倍、1.25倍、1.5倍、2.0倍等を同じ評価条件で比較できるようにする。
7. S7「CM-N1・通信混雑モデル」: 各船の理想送信をAISスロットへ配置し、Class別アクセス方式、同時送信、スロット再利用、競合をモデル化する。1.0倍で基準状態を校正し、追加交通による相対的な性能悪化を計算する。
8. S8「限界点評価」: 交通量倍率または同時航行隻数に対する、30km以内の欠落率・情報鮮度違反率・位置把握遅延を求める。限界基準を最初に超える負荷、その不確かさ、Class別・地域別差を提示する。

CM-E2、CM-E3、CM-P1は、S4・S5の残差分析と設備情報の取得状況に応じてS6～S8の前または並行で追加する。追加した場合も、モデル版と採用条件を固定し、同一の交通シナリオで比較する。
